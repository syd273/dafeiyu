# 大肥鱼 2.0 规划（本地优先版）

## 目标

- **本体**：大肥鱼 —— 有稳定性格、有长期记忆、能自己「看见」记忆的机器人
- **存储**：电脑提供 **10GB** 磁盘预算（不是内存），全部记忆/附件/快照都在里面
- **可视化**：记忆星图 2.0，**只给自己看**（本机 127.0.0.1 访问）
- **平台**：待定（Telegram 需要代理/账号；QQ 官方机器人合规免费）—— 平台层可后接，不影响本体

## 10GB 预算分配

| 项目 | 上限 | 策略 |
|---|---|---|
| `archive.db` | 3 GB | 原文+摘要+边；超限时把最旧消息转入冷分段（只留摘要） |
| `media/` | 5 GB | 附件按哈希去重；最旧优先清理 |
| `snapshots/` | 1.5 GB | 每日备份，保留最近 14 天，滚动覆盖 |
| `logs/` | 0.2 GB | 按天切分，保留 30 天 |
| 合计 | 9.7 GB | 留 0.3GB 缓冲 |

监控：`scripts/backup.py` 每天检查总占用，超 9GB 警告并按策略清理。

## 记忆内核数据模型

```sql
messages(id, ts, role, platform, umo, text, meta_json)   -- 全量原文
summaries(id, ts, kind, start_ts, end_ts, text, tokens)  -- 分段摘要
facts(id, ts, subject, predicate, object, confidence, msg_id) -- 长期事实
entities(id, name, kind)                                  -- 人物/地点/主题
edges(src, dst, kind, weight)  -- kind: time|entity|semantic|emotion
```

- 每轮对话 → `messages` 追加 → 抽取实体/事实 → 与上一条建 `time` 边、与共现实体建 `entity` 边
- 每晚：把 50 条以上连续消息压成 `summaries`；重算语义边（jieba 分词 + TF-IDF）
- 上下文超限时：近期原文 + 常驻摘要 + 检索命中片段（`/api/search` 同款检索）注入提示词

## 记忆星图 2.0

- **后端**：FastAPI + SQLite；`/api/graph` 返回 {nodes, edges}（分页/按时间窗）；`/api/node/{id}` 返回详情+原文；`/api/search?q=` 返回命中节点
- **前端**：D3 v7 力导向（canvas 渲染万级节点）；时间轴滑块过滤；按类型/情绪着色；搜索高亮；点击节点看详情卡
- **访问**：`http://127.0.0.1:8010`，只监听本机

## 风险与对策

- **Telegram 不可达**：平台先做 QQ 官方机器人（合规、无代理），Telegram 待有代理/账号后再接
- **磁盘超限**：自动分层（原文→摘要），星图只画摘要级+最近原文
- **隐私**：星图仅 127.0.0.1；备份可加密；`/忘记` 删除指定记忆
