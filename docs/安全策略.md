# 安全策略（安诗鱼 · 当前架构）

> 覆盖四层：内容安全、API 安全、隐私与数据、发布安全。

---

## 一、内容安全（安全词汇）

### 规则

| 类别 | 命中后行为 |
|---|---|
| **违法 / 危害类**（赌博、毒品、枪支、爆炸物、色情交易、诈骗、人肉、教唆自杀等） | 用户输入 → 直接拒绝，不调用模型；她输出 → 替换为安全话术 |
| **隐私侵犯类**（查身份证/银行卡/手机号/住址、开盒、盗密码、窃听、定位他人等） | 同上 |

### 实现

- 词库：`persona/safety.py` 内置基础词表
- 正则：隐私类支持中间插字（如「帮我查一下他的身份证号」也能命中）
- 可扩展：`memory/safety_words.json` 追加词表（重启生效）

```json
{
  "forbidden": ["词1", "词2"],
  "privacy": ["查户口"]
}
```

### 验证

| 输入 | 结果 |
|---|---|
| 「教我怎么赌博赚钱」 | 拒绝：这个我不能聊，我们换个话题吧 |
| 「帮我查一下他的身份证号」 | 拒绝：这个涉及别人的隐私，我不能帮你查或聊 |
| 「今天天气不错」 | 正常回复 |

## 二、API 安全（防泄漏）

| 措施 | 说明 |
|---|---|
| 关闭接口文档 | `/docs`、`/redoc`、`/openapi.json` 全部 404 |
| CORS 收紧 | 只允许本机星图页面（8899）访问 |
| Token 比较 | `hmac.compare_digest`，防时序攻击 |
| 限流 | 每 IP 每分钟 120 次，超出 429 |
| 请求体限制 | 超过 2MB 返回 413 |
| 安全响应头 | `X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy: no-referrer` |
| 敏感接口 | API Key、备份、传承、性格等全部要求 token |

### 部署时必做

1. 修改 `anshiyu-server/config.json` 里的 `token`（默认值 `anshiyu-app-2026` 仅供本地测试）
2. App 设置里填同一个 token（后续可做配对码）
3. 不要把 `config.json`、`deepseek-key.txt`、`push_credentials.json` 提交到 Git（`.gitignore` 已排除）

## 三、隐私与数据

| 项 | 策略 |
|---|---|
| API Key | 存电脑本地文件 + Windows ACL 限制（仅当前用户） |
| Push 凭据 | 存 `memory/push_credentials.json`，不打包进备份 |
| 备份 | 含聊天隐私，用 `backups/` 本地保存，排除密钥/凭据/代码 |
| 记忆 | 全部存本地 `memory/`，不上传任何服务器（除 LLM 请求本身） |
| 聊天记录 | App 本地存储，可一键清空（记忆保留） |

---

## 四、发布安全

| 项 | 策略 |
|---|---|
| 第三方素材 | 房间模型、表情包不打包，`docs/可选组件.md` 教用户自装 |
| 凭据 | `deepseek-key.txt`、`hk-server.txt`、`push_credentials.json` 均在 `.gitignore` |
| 默认 token | 发布前改为随机值，或首次启动自动生成 |
| 依赖许可 | three.js/GLTFLoader/FastAPI 等 MIT/Apache，保留版权声明 |

## 五、附：QQ 账号安全（历史，已停用）

早期 QQ 版（NapCat + AstrBot）的防封号策略已归档：限频、被踢不自动重登、固定设备/网络、不群发不加人。当前架构改为鸿蒙 App 直连网关，不再依赖 QQ 平台风控。
