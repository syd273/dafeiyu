# 鸿蒙端构建与部署

面向想自己编译、改包、真机调试或上架的人。内容来自 v1.0.0 上架过程中的实际操作记录。

## 一、环境

| 组件 | 版本 / 说明 |
|---|---|
| DevEco Studio | 5.x 及以上（自带 `hvigor`、`hap-sign-tool`、`hdc`） |
| HarmonyOS SDK | API 12+（本项目 `compatibleSdkVersion 6.1.1(24)`、`targetSdkVersion 26.0.0`） |
| Node.js | 18+（hvigor 需要） |
| Java | 用 DevEco 自带的 `jbr` 即可 |

工程目录：`app-harmony/`（`AppScope/` + `entry/` + `hvigor/`）。

## 二、先跑通后端

App 只是壳，聊天、记忆、星图都在电脑上：

```powershell
# 一键拉起：生活引擎 8910、网关 8900、星图 8899、记忆同步
powershell -ExecutionPolicy Bypass -File scripts\start_all.ps1
```

验证：

```powershell
curl http://127.0.0.1:8900/api/status
curl http://127.0.0.1:8899/
```

两个都返回 200 才算通。`8910` 返回 404 是正常的（它没有根路由）。

## 三、客户端配置

首次打开 App：**设置 → 本地服务器**，填 `http://<电脑局域网IP>:8900`，点「测试连接」→「保存本地」。

手机和电脑必须在同一个 WiFi。Windows 下查 IP：`ipconfig`，找无线网卡的 IPv4。

连接令牌在同页「连接令牌」填入，值取自服务端 `config.json` 的 `token`。

## 四、构建

### 方式一：DevEco Studio（推荐给首次接触的人）

1. 打开 `app-harmony/`
2. `File → Project Structure → Signing Configs`，勾选自动签名（需登录华为开发者账号）
3. 连手机 → 点运行

### 方式二：命令行

```powershell
$env:DEVECO_SDK_HOME = "D:\DevEco Studio\sdk"
$env:JAVA_HOME      = "D:\DevEco Studio\jbr"
$env:PATH           = "D:\DevEco Studio\jbr\bin;$env:PATH"

cd app-harmony
# 产物：build/outputs/default/*.app（含签名前的包）
& "D:\DevEco Studio\tools\hvigor\bin\hvigorw.bat" assembleApp --mode project -p product=default --no-daemon

# 只打 HAP（真机调试用）
& "D:\DevEco Studio\tools\hvigor\bin\hvigorw.bat" assembleHap --mode module -p product=default -p buildMode=debug --no-daemon
```

## 五、签名（最大的坑）

### 坑 1：hvigor 不接受短密码

`build-profile.json5` 里如果填的是明文密码且长度 < 32 位，`SignHap` 阶段会直接报错。这不是密码错了，是 hvigor 的密码格式限制。

**绕过办法**：先把签名配置摘掉，构建 unsigned 包，再用 `hap-sign-tool` 单独签。

```python
# 移除 signingConfigs（改完记得还原）
import re, pathlib
p = pathlib.Path(r"app-harmony\build-profile.json5")
s = p.read_text(encoding="utf-8")
s = re.sub(r'"signingConfigs":\s*\[.*?\n    \],\n', '', s, flags=re.S)
s = re.sub(r'"signingConfig":\s*"[^"]*",\n', '', s)
p.write_text(s, encoding="utf-8")
```

```powershell
java -jar "$env:DEVECO_SDK_HOME\default\openharmony\toolchains\lib\hap-sign-tool.jar" sign-app `
  -keyAlias "<别名>" -signAlg "SHA256withECDSA" -mode "localSign" `
  -appCertFile "signing\xxx.cer" -profileFile "signing\xxx.p7b" `
  -inFile "build\outputs\default\xxx-default-unsigned.app" `
  -keystoreFile "signing\xxx.p12" -outFile "dist\release.app" `
  -keyPwd "<密码>" -keystorePwd "<密码>"
```

### 坑 2：.app 的签名在外层

`.app` 是一个 zip（`pac.json` + `pack.info` + `entry-default.hap`），**签名块附加在整个 zip 外**。你把里面的 `.hap` 解出来单独装，会报 `9568320 no signature file`——这是正常的，不是包坏了。

## 六、安装到手机

```powershell
hdc list targets                      # 确认设备已连接
hdc install -r path\to\debug-signed.hap
```

**release 包不能直接 `hdc install`**（报 `9568322`）。正式包只能通过 AGC 的测试版或应用市场安装。

三个常见错误码：

| 错误码 | 含义 | 处理 |
|---|---|---|
| 9568320 | 无签名文件 | 装的是从 .app 里解出来的裸 hap，用 debug 签名重新构建 |
| 9568263 | 版本降级 | 手机上已有更高 versionCode，先卸载或提高 versionCode |
| 9568322 | 签名校验失败 | release HAP 直装，改用 AGC 测试版 |

## 七、上架要点（AGC）

### 必过的两个自动检测

| 检测项 | 要求 | 本项目的坑与解法 |
|---|---|---|
| 导航条适配 | 底部固定控件距屏幕底 ≥ **28vp** | 读取 `TYPE_SYSTEM.bottomRect` + `TYPE_NAVIGATION_INDICATOR.bottomRect` 相加，底部内边距 = 12 + 该值；并监听 `avoidAreaChange` / `windowSizeChange` 跟随折叠与旋转 |
| 冷启动加载完成 | ≤ **4000ms** | 首帧优先：网络请求延后、超时压到 1.5s、IP 探测 8 个 × 600ms；不要在首屏路径里同步等网络 |

### 素材规范

| 素材 | 规格 |
|---|---|
| 应用介绍截图 | 竖向 **1080×1920**（9:16），3~10 张，PNG/JPG ≤5MB |
| 应用介绍视频 | 与截图方向一致（竖向） |
| 推荐视频 | **1600×1200**（4:3），15 秒~2 分钟，≤500MB |
| 软件包 | ≤50MB |

> 截图方向是"整组"属性：选了竖向，介绍视频也必须竖向；横向只留给「推荐视频」。

### 上架前自检清单

- [ ] 隐私政策、用户协议已填入（建议用 AGC「隐私托管」，链接是 https）
- [ ] 一句话简介、应用介绍非空
- [ ] 发布版本指向的是本次新上传的包（**不要选成历史上的旧包**）
- [ ] 旧版本审核已撤销/删除，否则同版本号会冲突
- [ ] 上架自检跑完并通过

## 八、版本号策略

- `versionName` 是用户看到的版本（如 `1.0.0`）
- `versionCode` 是内部递增号（如 `1000000`），AGC 用它判断升降级
- **同 versionCode 不能重复上传**，被旧包占用时，可以只提 versionCode（如 `1000002`）而保持 versionName 不变

## 九、常见运行问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 顶栏一直「离线 / 重连」 | 服务器地址不对，或手机不在同一 WiFi | 设置页「测试连接」 |
| 星图黑屏 | 8899 服务没起，或地址不可达 | 现在会显示"星图服务没有连上"兜底提示 |
| 收不到通知 | 系统没给通知权限 | 系统设置里允许通知；Push Kit 需装 AGC 测试版验证 |
| 冷启动慢 | 网络不可达时在等超时 | 已压到 1.5s；仍慢就看是否开了软件包加密 |
